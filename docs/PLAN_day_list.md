## 2. 要做的事

### A1 行事曆的日期有錯(`macro_miner.py`)

- `FOMC_SCHEDULE`:**2026-12-16 是錯的**,官方是 12/8~9 → 決議日 `2026-12-09`。2027 那 8 個是「預填」的,多半不對 → 全部換成
  `research/us_cal.json` 的 `fomc`(2027:01-27、03-17、04-28、06-09、07-28、09-15、10-27、11-17)。
  ⚠️ 2027 最後一筆(11/16~17)跟前一筆(10/26~27)只差三週,官方頁面目前這樣寫 → 換之前再派一次 `macro_probe which=us_cal` 看 log 的「2026 / 2027 原文」。
  加測試:行事曆用的聯準會日期必須都在 `us_cal.json` 的 `fomc` 裡。
- CPI(每月 10~14 日第一個平日)、非農(第一個星期五)、MSCI(第三個星期四)、台積電法說(固定幾號)都是**規則湊的**。
  ALFRED 只有過去的公布日,沒有未來的 → 事件文字加「(大約)」;MSCI 的規則沒有根據 → 查 MSCI 官方的 index review 日程再定,查不到就標「(日期大約)」。⛔ 不可把湊的日期寫得像確定的。

### A2 行事曆的文字(`macro_miner.py` `_compute_upcoming_macro_events` / `_classify`)

- 拿掉沒有測試支持的話:「(提防外資結算洗盤)」「(選擇權結算,波動激增)」「(被動資金流向,大型股波動激增)」「(終極利空/利多)」「連假前後流動性低」「前後波動大」。
  換成只講是什麼(例:「🇹🇼 台指期月結算」)。
- `direction`(bearish / bullish / volatile)是關鍵字湊的,沒有任何測試 → 先 grep 誰在讀(11/17 時前端、worker、alert_system 都沒讀),整個欄位拿掉。
- `severity`:high 目前連動 App 的紅色橫幅與風險分數。改成兩件事分開:「大家都在看的大事件」(照舊列)與「測過比較顛」(只有長假後第一天)。
