# 回測探針（probe）

使用者已永久授權：**純回測／探針（只讀、不改 App 判定、不動 workflow）⛔ 不用問，直接做。**
⛔ **這支不做**：改 App 的判定邏輯（那是另一輪，且要先過六關）、動採礦、改 workflow。

## ① 先查「以前測過沒」（⛔ 最容易浪費一整輪的一步）

```bash
grep -n "關鍵字" docs/DECISIONS.md docs/EXTERNAL_REVIEWS.md
grep -n "關鍵字" CLAUDE.md        # 探針登記表（📋 一大張表，每支寫了「何時該重跑」）
```
⭐ 登記表裡標 **⛔ 已驗不成立** 的**別再測一次**；標 **⭐ 走完一次空頭後要重跑**的才值得重跑。

## ② 寫探針（樣板：`short_probe.py` 是目前方法學最完整的一支，可直接照抄）

- 只讀 `data/*.json`，⛔ 不打 API、⛔ 不寫檔到 `data/`
- 純 Python / 純 Node，⛔ 不加新依賴
- 要有 `--selftest`（合成資料 + 注入已知邊際，**確認 harness 量得出來**）
- 大量資料用分批處理，⛔ 不整包載進記憶體（1GB 主機）

### 🚨 前視偏誤三處最常犯
1. **法人／融資券／集保是收盤後才公布** → 訊號日不能用當天收盤進場，要**隔天開盤**
2. **百分位／排名用了含未來的整檔排序** → 一律 expanding（只看當天以前）
3. **條件用今天收盤、報酬也從今天收盤算** → 等於偷看答案

### 🚨 另外三個一定要做的
- **排除鎖漲停**（買不到就不能算賺到）
- **斷崖守門**：相鄰收盤比值 > 1.4 或 < 0.6 的整檔剔除（分割／減資殘留會製造 +1860% 的假訊號）
- **事件去重**：同檔同訊號 N 日內只算一次，⛔ 別報灌水後的 n

## ③ 六道關卡 + 兩道追加（⛔ 缺一關就是「這一段剛好比較好」）

| # | 關卡 |
|---|---|
| 1 | 全期為正 |
| 2 | 前後半段**同向** |
| 3 | **逐年**同向 |
| 4 | 去掉最好的那一年（或最好的那個月）仍成立 |
| 5 | 扣交易成本 **0.44%**（當沖來回約 0.25%）後仍為正 |
| 6 | **增量檢定**：疊在現行做法之上還有東西 |
| +1 | **買得到嗎**（鎖漲停／流動性） |
| +2 | **疊在現行配置之上**還有增量 |

另外兩件事：
- **乾淨對照組**：⛔ 不可只跟 0 或 50% 比。基準要用「同一條勝負定義掃全部交易日」算出來
  （全市場 10 日基準勝率實測 **36.4%**，不是 50%）
- **門檻高原檢定**：門檻左右各挪兩格仍成立才算數（孤峰 = 過擬合）
- **格內對照**：位階 × 波動 × 成交金額三分位，格內比才不會量到「大型股本來就穩」

## ⑤ 結論怎麼用

- **六關全過 + 判準是「總獲利最大」+ 是高原不是孤峰 + 窗口含一次空頭** →
  照 CLAUDE.md「策略預設值自動替換」規則**直接換**，但換完必做四件（`_STRAT_CHANGES` 跳窗、
  舊的留成選項、**所有呼叫點一起換含 `auto_trade.py`**、把引用舊成績的地方一起重跑）
- **任何一關沒過** → ⛔ 不換，寫進實測總表當紀錄
- **混用沒單獨測過** → ⛔ 不可把各自最佳值直接疊起來
- 數字說贏的時候**更要**把限制寫在旁邊（窗口偏多頭／倖存者偏誤／中途最多賠多少）
