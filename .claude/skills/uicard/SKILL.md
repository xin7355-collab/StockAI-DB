# 前端卡片／介面（uicard）

⛔ **這支不做**：改判定邏輯或門檻（那要先走 **probe** 回測過六關）、動採礦。

## ① 動手前先問三個問題

1. **能不能併進既有卡片？** 使用者鐵則：**合併卡片，⛔ 不要一直加新卡**
2. **這顆燈是在講方向，還是在講風險？**（決定能不能用 🔴🟢，見 ②）
3. **使用者在什麼情境會問這個問題？** → 決定放哪個頁籤
   （上檔空間 → 進場頁 ・ 防守價 → 出場頁；⛔ 放錯 = 使用者找不到 = 等於沒做，陷阱 #32）

## ② 🚦 燈號鐵則（使用者明示，⛔ 不可違反）

- 🔴🟢 **只准表示漲跌方向**（🔴=偏多/上漲、🟢=偏空/下跌），台股慣例紅漲綠跌
- **風險／通過與否**一律用非顏色圖示：
  **✅ 安全 ・ ⚠️ 警戒 ・ ⛔ 危險 ・ 🚨 緊急(animate-pulse) ・ 💀 必死 ・ ➖ 中性 ・ ⏳ 資料不足 ・ 💡 提示**
- 文字顏色照台股慣例不變，**只有 emoji 改**
- 內部代碼可保留舊值，但**會顯示給使用者的字串一律照上面改**

## ③ 🚪 會下操作指令的卡：兩道守門都要過

```js
if (app._bearGate(sym)) { /* 這檔是空頭 → 操作指令改成「反彈減碼」 */ }
const mk = app._mktGate();  // 大盤過熱/轉弱/盤整 → 措辭降級
if (app._inExitMode(sym)) { /* 出場狀態 → 走 _exitModeNoticeHtml() */ }
```

⚠️ **事實描述不動**（「今天比大盤強」是真的，不可竄改），要改的只有**那句叫人怎麼做的話**。
🚨 **守門要「換掉那句指令」，⛔ 不是在後面補一句但書** ——
「可依紀律進場，**但**大盤過熱…」前半仍是完整指令，使用者只會讀粗體那半。
正解：「**條件是到了**（事實），但大盤 X、總部位 Y → **只能小量，⛔ 別追高**（指令）」。

⭐ 這個錯全 App 已犯 **10 次**（每次都以為是個案）→ 新增任何會講
「可以進場／抱好／加碼／順勢做多」的卡，**先呼叫這兩道**。

## ④ 🧰 共用函式（⛔ 別自己再寫一份 —— 陷阱 #37：規則只活在文件裡）

| 要顯示什麼 | ⛔ 一律走 |
|---|---|
| 賺／賠多少元 | `app._netPL(buy, sell, shares)` + `app._feeDisc()` |
| 上檔目標／壓力價位 | 加進 `app._upsideRoom(pC, data, last)` 的來源清單，顯示端讀 `_upsideStash` |
| 資料日期 | `app._dW(raw, {y, rel})` ・過期提醒 `app._dChip(raw, '標籤')`（⛔ 禁自己拼日期字串） |
| 勝率 | `app._wrTag(wr, n, p0)`；**n < `_wrEnough`(10) ⛔ 不准下進場指令**；`p0` 傳**該場景自己的基準**（⛔ 不是 0.5） |
| 美股／總經指標 | `app._macroPick(key)` / `app._macroChg(key)`（兩份檔形狀不一樣） |
| VIX | `app._vixState()` |
| 外資期貨 | `app._fiFutState()`（⛔ 絕對口數門檻已作廢） |
| 成交金額 | `app._amtState()`（回傳 `label`，⛔ 呼叫端不准自己寫死名字） |
| 該買幾張 | `app._lotsForRisk(price, stop)` |
| 訊號實測成績 | `app._sigEdge(det, title)`；收訊號用 `_tagPush(sigs, '_detectX', data)` |

新增任何「一律改用 X」的規則時，**當場 grep 舊寫法還有幾處、逐一接完，再寫一條測試釘住**。

## ⑤ 🗣️ 同名不同義（使用者講最多次的「邏輯不打架」）

- **同一個名詞全 App 只能有一個數字；不同公式就要不同名字**
- 兩個指標黏成一句話之前，先問「**它們會不會相反**」——
  相反時⛔ 不可並排，要把矛盾明講出來（「籌碼乾淨，**但大戶倒貨給散戶**」）
- **顯示的 % 與由它換算的金額必須自洽**（使用者會拿畫面上的數字驗算 → 用**顯示值**回算金額）
- **任何 `a/(a+b)` 的占比**：先問 a+b 夠不夠大；一邊掛 0 時要寫「可能只是資料沒到齊」，
  且百分比旁一定要同時顯示「命中 N/M」
- **「沒有資料」與「條件不成立」是兩件事** → 缺資料標 `na:true`，分母用 `applicable`（⛔ 不寫死）
- **「N/M 條通過」的卡必須同時顯示門檻與還差幾條**，且兩個數字從同一個式子算

## ⑥ 🎨 版面（樣板一律引用 CLAUDE.md「UI/UX 設計規範」，⛔ 別重新設計）

- 背景 `bg-[#161b22]` / 邊框 `border-[#30363d]`；⛔ 禁霓虹漸層
- 重要數字 `text-2xl font-black font-mono`，副字 `text-[10px]`；**% 一定順便給實際金額**
- ⛔ **手機上的資料列，欄位 ≥3 個就別用 table** → 改「一行一張卡」
- 長內容包 `overflow-x-auto` 自己滾，⛔ 不准撐寬整頁；`flex-1` 記得配 `min-width:0`
- 每張複雜卡右上加「📖 教學」，風險警報下方加「💡 對策」一句話
- 沒命中時 `hidden`（⛔ 不留空殼）；算不出來整條不顯
- 圖表 label 禁裸放 → 加 `backgroundColor:'rgba(13,17,23,0.85)'` + padding
